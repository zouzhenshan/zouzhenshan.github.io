Unitree G1 人形机器人 AMP-MoE 多技能运动控制

开发融合多技能与人类动作的运动控制策略，实现本体感知下的多地形盲走、抗扰平衡及跌倒起身。

Aug 12, 2026

项目背景

控制对象为 Unitree G1 23 DoF 机器人，部署侧控制周期为 0.02 s，策略输出为 23 维 raw action，经缩放转换为关节目标。项目中预训练了两个主要专家：

  • 行走专家：DWAQ + AMP 训练得到，覆盖多地形行走、转向、上下台阶等移动能力。
  • 起身专家：AMP get-up 策略，覆盖摔倒后的恢复站立。

如果只把两个专家简单硬切换，机器人在切换瞬间会遇到三个问题：

  1. 两个专家输出动作差距大，目标关节会突然跳变。
  2. 新切换的专家的历史观测里仍然包含上一专家执行过的动作，这是教师训练时没有见过的分布。
  3. 路由判断一旦在临界状态抖动，会放大动作跳变，表现为抽搐、僵直或二次跌倒。

因此本项目的核心是设计一套能让多个运动技能在闭环中稳定共存的融合机制。

图 1：AMP-MoE 总体架构。统一 510D 历史观测同时进入 walking expert、recovery expert、neural route heads 和 STABLE_HOLD gate；路由头负责离散状态切换，门控网络只在 STABLE_HOLD 状态对两个专家动作做加权软融合。

教师专家策略训练

先让 walking expert 和 recovery expert 在各自支持域内足够稳定，再把主要工程难点集中到路由、历史分布对齐和切换连续性上。

Walking expert：DWAQ + AMP 多地形盲走

walking expert 的目标是提供可部署的本体感知行走能力，覆盖平地速度跟踪、转向、上下台阶和轻度复杂地形。策略不依赖外部视觉输入，而是使用 proprioception history、关节状态、上一拍动作和速度命令等信息，通过隐变量估计补偿不可直接观测的地形 / 速度扰动。

训练上采用 PPO 主干，并联合 VAE 辅助任务与 AMP 判别器。PPO 负责速度跟踪、稳定性、能耗和接触行为等任务目标；VAE 辅助头学习从历史观测中估计速度和隐变量，提高盲走时对地形与动力学扰动的适应；AMP 判别器则约束动作风格，使行走、跑步和转向更接近参考运动数据。

walking expert 的训练重点包括：

  • 使用多地形 curriculum，从平地速度跟踪逐步扩展到上下台阶和轻度粗糙地形。
  • 在命令采样中覆盖前进、后退、横移、原地转向和 yaw tracking，避免策略只在单一速度方向上表现好。
  • 加入摩擦、PD gain、motor strength 和 action delay 等域随机化，为后续 sim2real 留出鲁棒性。
  • 保持 walking context encoder 在后续 MoE 训练中冻结，避免 DAgger / residual 阶段破坏已经验证过的台阶和速度跟踪能力。

这个专家承担 MoE 中的“默认运动能力”：只要机器人处于直立或接近直立状态，系统就优先信任 walking expert，而不是让恢复策略长期参与正常行走。

Recovery expert：AMP get-up 跌倒恢复

recovery expert 的目标是覆盖机器人从摔倒、侧躺、仰躺、俯卧等非站立姿态恢复到稳定站立的过程。它和 walking expert 的状态分布差异很大：训练数据中包含大量身体、手臂、膝盖、躯干与地面的接触，动作目标不是速度跟踪，而是尽快建立支撑、抬升躯干、调整双脚落点并回到稳定站姿。

训练时使用 AMP get-up 任务，把参考起身动作作为风格先验，同时叠加明确的任务奖励。奖励设计更关注恢复过程中的阶段性目标，例如 base height、upright、双脚支撑、角速度降低、足部站宽 / 前后对齐、恢复时间和非期望身体接触惩罚。相比直接追踪单条 motion，AMP 能让策略在不同摔倒初始姿态和随机扰动下仍保持自然动作风格。

recovery expert 的训练重点包括：

  • 使用随机初始化和跌倒姿态采样，覆盖不同朝向、不同身体接触和不同恢复入口。
  • 对关键身体接触设置奖励与惩罚，允许恢复早期合理接触地面，但在站稳后抑制躯干、膝盖、手臂等非期望接触。
  • 加入恢复时间代价和稳定站立奖励，促使策略不是“做完动作”，而是真正闭环站稳。
  • 移除对手部刚体接触的依赖，针对实机手部非刚体、地垫形变和高摩擦地面重新微调 recovery 行为。
  • 对 recovery observation 做 term-wise clip，抑制 PhysX depenetration 或实机接触冲击带来的极端观测值。

这个专家承担 MoE 中的“安全恢复能力”：当路由判断当前姿态已经离开 walking 支持域时，系统切入 recovery expert，并在恢复完成后通过 STABLE_HOLD gate 和 handoff 逻辑平滑交还给 walking expert。

MoE 融合架构

最终部署模型保持单一输入输出契约：510D observation -> 48D packed output。48 维输出由四部分组成：

  • a_walk：23 维行走专家动作。
  • a_recovery：23 维起身专家动作。
  • p_need_recovery：是否需要进入恢复模式的神经路由概率。
  • p_ready_to_handoff：是否已经适合从恢复模式交还给行走模式的神经路由概率。

路由概率不直接作为动作混合系数，而是驱动一个带 hysteresis 和 timer 的部署状态机。实际控制采用：WALKING/FALLING 使用行走专家，RECOVERING 使用起身专家；STABLE_HOLD 引入 MoE 门控网络，对 walking / recovery 两个专家动作做加权软融合；HANDOFF 以 walking expert 为主，并通过命令 ramp 平滑恢复用户速度指令。

选择这个结构的原因：两个专家的状态分布差距过大，可明确区分时不需要加权融合动作输出，因此我只在这个边界状态使用门控软融合。实机部署时可解释性和安全边界仍然重要，所以神经网络负责判断恢复需求、交接时机和局部融合权重，确定性 supervisor 负责模式滞回、超时、启动状态、FAILSAFE 和命令置零等规则。

多技能融合处理

1. 神经路由与门控融合分工

路由网络只学习两个语义判断：

  • 当前状态是否需要 recovery expert 接管。
  • recovery 是否已经稳定到可以 handoff 回 walking expert。

状态机使用进入/退出阈值、hold time 和 handoff duration 来避免边界抖动。这使路由输出可以有一定噪声，但控制模式不会逐帧来回跳。

门控网络只在 STABLE_HOLD 状态启用，输出一个标量权重 w_stable ∈ [0, 1]：

1

a_stable = w_stable * a_walk + (1 - w_stable) * a_recovery

其中 w_stable 接近 0 时更依赖 recovery expert 的站稳能力，接近 1 时更依赖 walking expert 的默认站立 / 起步能力。这样路由网络仍负责“是否进入 recovery / 是否可交接”的离散语义，门控网络只负责 STABLE_HOLD 内部的连续动作接力。

2. DAgger 解决教师没见过的融合分布

单独训练的 walking expert 和 recovery expert 都只见过自己的闭环分布。MoE 融合后，入站专家会读到另一专家刚刚执行过的动作历史，这属于明显的 out-of-distribution 输入。

本项目使用在线 DAgger 解决这个问题：训练时同时推进 oracle supervisor 和 student supervisor，episode 级采样由 oracle 或 student 执行动作，所有真实闭环状态都写入持久化分层 replay buffer。冻结教师只提供标签，学生专家和 route heads 在融合系统真实访问到的历史分布上学习。

buffer 按场景分层采样，覆盖平地 locomotion、上下台阶、跌倒恢复、stable handoff、near-fall、高角速度、recovery stuck 和二次跌倒等 hard cases。这样做的重点是让数据分布服务于系统故障模式，而不是只追求平均 imitation loss。

图 2：在线 DAgger 训练闭环。oracle supervisor 与 student supervisor 并行推进，通过 episode 级 beta 选择执行源，真实闭环状态写入 stratified replay；冻结教师提供标签，学生专家、route heads 和 STABLE_HOLD gate 在融合系统实际访问到的分布上更新。

3. 切换边界连续损失降低动作跳变

针对状态 / 任务的切换顿挫，本项目加入了切换边界连续损失。核心思想是：与其完全依赖部署侧限速，不如让入站专家的 raw action 本身学会从上一拍实际执行动作附近出发。

在发生专家切换的帧上，损失直接约束入站学生专家动作与 a_executed(t-1) 的距离。这个设计让学生专家在融合闭环分布里学会更自然的接力。后续引入 STABLE_HOLD 门控后，边界连续损失还可以作用到融合后的 a_stable，让门控权重本身也受到动作平滑目标约束。

4. STABLE_HOLD 门控网络训练

STABLE_HOLD 门控网络目标是在 recovery 完成后到 handoff 前的短窗口内减少动作跳变和站立抖动。是在实机部署测试后的优化处理，在 neural module 中增加一个轻量 gate head：

1

w_stable = sigmoid(g(obs_510, p_need_recovery, p_ready_to_handoff, handoff_progress))

训练方式采用分阶段方案：

  1. 先冻结 walking / recovery 两个专家和 route heads，只训练 gate head，避免一开始破坏已验证的专家能力。
  2. 从 DAgger replay 中筛选 STABLE_HOLD、recovery -> stable、stable -> handoff 的边界帧，额外提高这些样本的采样比例。
  3. 用 oracle supervisor 生成候选标签：刚进入 stable 时偏向 recovery，稳定时间增长、躯干姿态接近直立、角速度下降、双脚支撑稳定后逐步偏向 walking。
  4. 损失函数由三部分组成：融合动作与 oracle final action 的 Huber imitation loss、相邻帧 w_stable 的 temporal smoothness loss、融合后动作与上一拍执行动作的 boundary continuity loss。
  5. 加入 gate entropy / saturation 正则，让 gate 在明显状态下接近单专家，在边界状态下才保留软融合，而不是长期输出模糊权重。

部署安全约束上，gate 只在 STABLE_HOLD 内生效；WALKING/FALLING/RECOVERING/FAILSAFE 仍沿用原来的确定性 expert selection。若 gate 输出非有限值、状态超时或姿态再次变差，supervisor 直接回退到 recovery 或 FAILSAFE。这样可以把软融合限制在“已基本站稳但尚未恢复行走命令”的低风险窗口里。

5. 残差微调保持保守可控

从冻结的学生策略分叉，加入 bounded residual：

1
2

a_walk = a_walk + delta_walk_max * tanh(r_walk(obs_510))
a_rec  = a_rec  + delta_rec_max  * tanh(r_rec(obs_510))

残差网络为 510 -> 128 -> 64 -> 23 的 MLP，输出层零初始化，因此第 0 步与 P3 tensor-exact。逐关节 residual bound 被注册为 buffer，保证 PPO 探索也不能突破设定边界。在 action scale 为 0.25 的部署设置下，walking nominal target 偏移约束在 0.01-0.02 rad 量级，recovery 约束在 0.015-0.035 rad 量级。

这让微调具有两个好处：一方面可以通过 RL reward 补偿真实闭环中的不足，另一方面不会轻易破坏已经验证过的行走和起身能力。

训练过程中的工程设置

  1. 先训练并验证教师策略 walking expert 和 recovery expert。
  2. 训练 neural route heads，让冻结专家可以由神经路由接管。
  3. 使用 DAgger 联合蒸馏，逐步解冻 recovery student 和 route heads，让专家适应融合后的真实历史分布。
  4. 在 STABLE_HOLD 状态加入门控网络，先冻结专家只训练 gate head，再用边界连续损失和时序平滑损失约束软融合动作。
  5. 用 residual-first PPO 做保守微调，引入推力、摩擦、PD/motor strength 和执行器延时等鲁棒性课程。
  6. 针对实机暴露的问题，进一步做 no-hand recovery 与微调修正。

训练细节包括：

  • route observation 排除速度命令，只基于身体状态判断是否需要恢复。
  • walking context encoder 全阶段冻结，保护台阶和速度跟踪能力。
  • DAgger 使用分层 replay，不让大量普通行走帧淹没 near-fall、二次跌倒和 handoff 边界样本。
  • imitation loss 使用 support mask，避免在教师本身不支持或失败的状态上强行模仿。
  • residual PPO 中只有当前 FSM 选中的 expert family 参与 actor update，inactive head 不注入梯度； STABLE_HOLD gate 训练会单独记录融合权重和融合动作，避免和 residual update 混淆。
  • 部署前导出 TorchScript、ONNX packed/named 模型，并用 Python/C++ 测试检查 observation contract、supervisor、limiter 和 ONNX Runtime 等价性。

图 3：阶段式训练路线。先得到 walking / recovery 教师专家，再逐步加入 rule FSM、neural route、DAgger student、STABLE_HOLD gate、bounded residual PPO 和 no-hand sim2real 修正，每一步都保留部署契约和回退路径。

部署侧状态机与安全契约

部署侧保留 C++ supervisor，而不是把全部逻辑塞进神经网络。关键规则包括：

图 4：部署侧 C++ supervisor 控制循环。ONNX policy 输出专家动作和路由概率，C++ supervisor 负责状态机、STABLE_HOLD gate blend、handoff command ramp 与 FAILSAFE passive damping，最终生成 PD targets 并闭环回到机器人状态估计。

  • startup 时根据实时姿态进入 WALKING、RECOVERING 或 FAILSAFE，避免非站立启动被错误当作正常行走。
  • recovery 期间速度命令置零，STABLE_HOLD 阶段计划使用 gate 对 walking / recovery 动作软融合，handoff 阶段用 alpha ramp 恢复用户命令。
  • 历史观测在 reset 后用首个有效物理帧填充，last_action 使用上一拍 supervisor 实际执行动作。

Sim2Real 遇到的问题

初期实机部署主要问题来自三个现实因素：

  1. G1 手部不是理想刚体。仿真中的 hand / wrist 接触与实机明显不同，起身时手臂或手部接触地面会引入非预期形变和冲击。
  2. 实验地面摩擦系数较高，和训练里默认材质存在差异，导致恢复动作中的脚底滑移无法实现、支撑转换和上身接触时序变化。
  3. 地面不是刚性平面，而是铺在瓷砖上的海绵垫。海绵垫会形变，也会相对瓷砖滑动，机器人起身过程中等于同时遇到可形变接触和整体地面滑移。
